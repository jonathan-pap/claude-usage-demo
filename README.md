# claude-usage

A personal multi-machine Claude API usage dashboard. Reads the JSONL session logs that Claude Code writes locally, aggregates token consumption across machines and projects, and produces a set of static HTML pages — no server, no build step, no framework.

**[▶ Live demo](https://jonathan-pap.github.io/claude-usage-demo/)** — ten months of synthetic data so you can explore before committing.

---

## How it works

```
Claude Code session
       │
       ▼
~/.claude/projects/**/*.jsonl   ← written automatically by Claude Code
       │
       ▼
  update_usage.sh               ← run on each machine (manually or via cron)
       │  • parses JSONL logs with ccusage
       │  • builds daily totals, token breakdown, cache ROI
       │  • runs build_insights.py  → project/tool/subagent attribution
       │  • writes machines/<hostname>.json
       │
       ▼
  git commit + push             ← machine snapshot committed to your repo
       │
       ▼
  GitHub Pages                  ← static HTML reads the committed JS data files,
                                   renders charts — no server needed
```

Multiple machines each commit their own snapshot. The dashboard merges them client-side, so you see a unified view of all activity regardless of which machine did the work.

## Quick start

### 1. Prerequisites

| Tool | Check |
|---|---|
| Git | `git --version` |
| Node.js 22+ (LTS) | `node --version` |
| Python 3.10+ | `python --version` |
| Bash | Git Bash on Windows, native on macOS/Linux |
| Claude Code | Must have session data under `~/.claude/projects/` |

### 2. Fork this repo

Click **Fork** (top-right on GitHub) and create a private repo under your account. Private is recommended — your usage data will be committed here.

### 3. Clone your fork

```bash
git clone https://github.com/YOUR-USERNAME/claude-usage.git
cd claude-usage
```

### 4. Enable GitHub Pages *(optional — for web access)*

Go to **Settings → Pages**, set source to **Deploy from branch → main → / (root)**.

Your dashboard will be live at `https://YOUR-USERNAME.github.io/claude-usage/` after the first push.

### 5. Run the updater

```bash
bash update_usage.sh
```

This will:
- Parse your Claude Code session logs
- Generate daily cost/token data
- Build project and tool attribution
- Commit and push a machine snapshot to your repo
- Replace the demo data with your real data

**That's it.** Open `index.html` locally (or your GitHub Pages URL) to see your dashboard.

## Keeping it up to date

Run `bash update_usage.sh` whenever you want to refresh. Add it to a cron job or scheduled task to run automatically:

```bash
# macOS / Linux — every day at 8am
0 8 * * * cd /path/to/claude-usage && bash update_usage.sh >> ~/claude-usage.log 2>&1
```

On Windows, create a Scheduled Task pointing to Git Bash:
```
Program: "C:\Program Files\Git\bin\bash.exe"
Arguments: -c "cd /c/path/to/claude-usage && bash update_usage.sh"
```

## Multi-machine setup

Run `bash update_usage.sh` on each machine you use Claude Code on. Each machine commits its own snapshot file (`machines/<hostname>.json`). The dashboard automatically merges all snapshots into a combined view.

---

## Data files

These are committed to your repo and served by GitHub Pages:

| File | Contents |
|---|---|
| `usage_data.js` | Daily token and cost totals |
| `insights_data.js` | Project, tool, model, subagent attribution |
| `machines/<hostname>.json` | Per-machine snapshots |
| `machines/all_machines.js` | All snapshots merged |
| `machines/manifest.js` | Machine list for the multi-machine banner |

`usage_history.json` and `insights.json` are generated locally and gitignored — they contain raw paths and are not committed.

---

## Privacy

The pipeline strips personally identifiable data before committing:
- OS username (`user` field) — omitted
- Full filesystem paths (`cwd`, `projects` keys) — replaced with project name only

Your usage costs, token counts, and project names are committed. Keep the repo private if you don't want this visible.
